# 20.1 Istio Labeling and Annotation Guide (Exam Reference)

This file consolidates all critical labels and annotations used for Sidecar Injection, Ambient Mesh, Discovery, Canary Upgrades, and Gateway management.

---

## 1. Namespace Labeling

### Sidecar Injection (Traditional)
Used to tell `istiod` which namespaces should have sidecars automatically injected.

| Label | Value | Description |
| :--- | :--- | :--- |
| `istio-injection` | `enabled` | Standard injection using the default revision. |
| `istio-injection` | `disabled` | Explicitly prevents injection (overrides pod-level). |
| `istio.io/rev` | `<revision-tag>` | **Targeted Injection:** Used for revisions. By itself, it defaults to **Sidecar Mode**. |

### Ambient Mesh
Used to opt-in a namespace to the sidecar-less Ambient data plane. **Note:** Ambient mode REQUIRES the `dataplane-mode` label.

| Label | Value | Description |
| :--- | :--- | :--- |
| `istio.io/dataplane-mode` | `ambient` | **CRITICAL:** MUST BE PRESENT to enable Ambient (ztunnel). |
| `istio.io/rev` | `<revision-tag>` | Specifies which control plane manages the ztunnel/waypoint. |

---

## 2. The "Revision vs Mode" Rule (ICA Exam Tip)

| If you want... | Labels Needed | Result |
| :--- | :--- | :--- |
| **Sidecar (Revisioned)** | `istio.io/rev=<tag>` | Pod gets `istio-proxy` sidecar. |
| **Ambient (Default)** | `istio.io/dataplane-mode=ambient` | Pod traffic intercepted by Node Ztunnel. |
| **Ambient (Revisioned)** | `istio.io/rev=<tag>` **AND** `istio.io/dataplane-mode=ambient` | Pod is Ambient, managed by revision `<tag>`. |

> **Warning:** Having `istio.io/rev` without `dataplane-mode=ambient` will ALWAYS trigger **Sidecar Injection**.

## 3. Pod & Workload Labeling/Annotations

### Discovery Selection (discoverySelectors)
By default, `istiod` watches **EVERY** namespace in the cluster. In huge clusters, this causes massive CPU/memory usage. You can use `discoverySelectors` to restrict Istio to only "see" specific namespaces.

**Configuration (Inside IstioOperator or MeshConfig):**
```yaml
spec:
  meshConfig:
    discoverySelectors:
      - matchLabels:
          istio-discovery: "true"
```

**Result:**
*   If a namespace is labeled `istio-discovery=true`, Istio will process its Services, Endpoints, and Istio CRDs.
*   If a namespace **lacks** the label, it is invisible to Istio. This means services in the mesh cannot route to it, and its sidecars (if any) won't receive updates.

## 3. Pod & Workload Labeling/Annotations

### Sidecar Control (Overriding Namespace)
Used when you want a specific pod to behave differently than its namespace default.

| Type | Key | Value | Description |
| :--- | :--- | :--- | :--- |
| **Annotation** | `sidecar.istio.io/inject` | `"true"/"false"` | Manually enable/disable sidecar for a specific pod. |
| **Label** | `sidecar.istio.io/inject` | `"true"/"false"` | Same as above (supported in newer versions). |
| **Label** | `security.istio.io/tlsMode` | `istio` | Added by Istio to pods to indicate they support mTLS. |

### Discovery & Metrics (ICA Exam High Priority)
Istio uses these to determine the "Identity" and "Version" of your application.

| Label | Value | Importance |
| :--- | :--- | :--- |
| `app` | `<app-name>` | Used for telemetry and service matching. |
| `version` | `<v1/v2>` | Used by `VirtualService` destination subsets and telemetry. |
| `app.kubernetes.io/name` | `<name>` | Standard K8s label (Istio-aware). |
| `app.kubernetes.io/version` | `<version>` | Standard K8s label (Istio-aware). |

### Traffic Management Annotations
| Annotation | Value | Description |
| :--- | :--- | :--- |
| `traffic.sidecar.istio.io/excludeOutboundPorts` | `"3306,5432"` | List of ports to bypass the Envoy proxy (e.g., DBs). |
| `traffic.sidecar.istio.io/includeInboundPorts` | `"*"` | Which ports should be intercepted by Envoy. |
| `proxy.istio.io/config` | `"{ ... }"` | Per-pod Envoy configuration overrides (advanced). |

## 3. Canary Upgrades (Revision Labeling)

During a Canary upgrade (e.g., moving from `1.21` to `1.22`), you must manage labels to transition traffic.

### Step 1: Install New Revision
The new control plane installation will have a label like `istio.io/rev=1-22-0`.

### Step 2: Test a Namespace
Update the namespace to point to the new revision:
```bash
# Remove old label
kubectl label namespace my-ns istio-injection-
# Add revision label
kubectl label namespace my-ns istio.io/rev=1-22-0
```

### Step 3: Verify Pods
The new pods will have the annotation:
`istio.io/rev: 1-22-0`

## 4. Gateways & Ingress

### Gateway Selection
The `Gateway` (CRD) must select the correct `Deployment` running the Envoy Gateway.

| Label in Gateway Spec | Destination Deployment Label | Description |
| :--- | :--- | :--- |
| `selector: { istio: ingressgateway }` | `istio: ingressgateway` | Standard mapping for public ingress. |

### Ambient Waypoint Selection
Waypoints are applied per-service or per-namespace.

| Annotation | Value | Description |
| :--- | :--- | :--- |
| `istio.io/use-waypoint` | `<waypoint-svc-name>` | Added to a **Service** or **Namespace** to route through L7 Waypoint. |

## 5. Security (mTLS & PeerAuthentication)

| Label/Annotation | Value | Description |
| :--- | :--- | :--- |
| `istio.io/mutual-tls` | `true` | Internal label indicating mTLS is active on an endpoint. |
| `security.istio.io/skip-export` | `"true"` | Annotation to prevent a service from being exported to other namespaces. |

## 6. Summary Command Table for Exam

| Task | Command |
| :--- | :--- |
| **Label Namespace for Sidecar** | `kubectl label ns <name> istio-injection=enabled` |
| **Label Namespace for Ambient** | `kubectl label ns <name> istio.io/dataplane-mode=ambient` |
| **Label Namespace for Revision** | `kubectl label ns <name> istio.io/rev=1-22-1` |
| **Check Labels on All Namespaces** | `kubectl get ns --show-labels` |
| **Check Revision of Running Proxies** | `istioctl proxy-status` |
| **Find Pods with Sidecars** | `kubectl get pods -A -l security.istio.io/tlsMode=istio` |
