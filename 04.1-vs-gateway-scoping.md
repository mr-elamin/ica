# 04.1 VirtualService Gateway Scoping

A common source of confusion in Istio is the **`gateways`** field. It appears in two places in a `VirtualService`, but they serve very different purposes.

---

## 1. Top-Level `spec.gateways`
This is the "Binding" field. It tells Istio: *"Apply this entire VirtualService to these specific gateways."*

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: my-app
spec:
  hosts:
  - "app.example.com"
  gateways:
  - my-ingress-gateway   # Binding: This VS is active ONLY on this gateway
  - mesh                 # Binding: This VS is also active for internal sidecar traffic
  http:
  - route:
    - destination:
        host: my-app-svc
```

---

## 2. Match-Level `http.match.gateways`
This is a **Filter**. It allows you to have different routing logic for the **exactly same host** depending on which gateway the traffic entered through.

### Example Scenario:
You have a public gateway for customers and a private gateway for employees. Both access `api.example.com`, but you want customers to go to `v1` and employees to go to `v2`.

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: api-routing
spec:
  hosts:
  - "api.example.com"
  gateways:
  - public-gw
  - private-gw
  http:
  # Rule 1: Only matches if traffic came through the public-gw
  - match:
    - gateways:
      - public-gw
    route:
    - destination:
        host: api-svc
        subset: v1

  # Rule 2: Only matches if traffic came through the private-gw
  - match:
    - gateways:
      - private-gw
    route:
    - destination:
        host: api-svc
        subset: v2
```

### Why use `http.match.gateways`?
1. **Security:** Prevent internal-only routes from being accidentally exposed on the public gateway even if they share the same Host header.
2. **Context-Aware Routing:** Route to different backends based on the "Entry Point" of the traffic.
3. **Multi-Gateway Management:** Consolidation of multiple routing policies for the same domain into a single `VirtualService` file.

---

### Key Summary Table

| Field Location | Role | Purpose |
| :--- | :--- | :--- |
| **`spec.gateways`** | **Binding** | Determines which Proxies (Gateways/Sidecars) receive the config. |
| **`spec.http.match.gateways`** | **Filtering** | Determines which route to take based on the "source" gateway name. |
