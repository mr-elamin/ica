# 19.1 Istio Troubleshooting Cheat Sheet (ICA Exam Quick Reference)

This cheat sheet provides a high-yield command reference for diagnosing configuration, control plane, data plane, and network traffic issues in Istio.

---

## 1. Configuration Validation & Static Analysis

| Task | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **Analyze Live/Local Config** | `istioctl analyze` | Scans live cluster resources or local YAML files for logical errors, unreachable routes, mTLS conflicts, missing selectors, deprecated fields, etc. |
| **Validate Manifest Syntax** | `istioctl validate -f <file.yaml>` | Validates YAML structure and schema compliance for `Service`, `Deployment`, and `IstioOperator` manifests (e.g., checks port naming rules, canonical labels). |

---

## 2. Control Plane (`istiod`) Diagnostics

| Task | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **View Control Plane Logs** | `kubectl logs -n istio-system deploy/istiod` | Checks if configurations were rejected, static `ServiceEntry` has missing endpoints, or push errors occurred. |
| **ControlZ Dashboard** | `istioctl dashboard controlz deploy/istiod -n istio-system` | Opens interactive web UI to inspect `istiod` memory, runtime args, environment vars, and modify `istiod` logging scopes on the fly. |

---

## 3. Data Plane Sync & Status (`proxy-status` / `ps`)

| Task | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **Check xDS Sync Status** | `istioctl proxy-status` (or `istioctl ps`) | Displays sync state (`SYNCED`, `STALE`, `NOT SENT`, `IGNORED`) for CDS, LDS, EDS, RDS, WDS across all proxies. |
| **Check Specific Proxy Sync** | `istioctl ps <pod-name>.<namespace>` | Isolates sync state for a single sidecar/gateway pod. |

*   **`SYNCED`**: Envoy has acknowledged the latest configuration from `istiod`.
*   **`STALE`**: Configuration push is delayed or pending.
*   **`IGNORED`**: Required resource is missing (e.g., Ingress Gateway showing `RDS IGNORED` means a `Gateway` resource is missing).

---

## 4. Envoy Proxy Configuration Deep-Dive (`proxy-config` / `pc`)

`istioctl proxy-config` (short alias: `istioctl pc`) extracts active Envoy configuration directly from a sidecar or gateway proxy.

| Subcommand / Option | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **List Clusters** | `istioctl pc cluster deploy/httpbin` | Shows upstream targets (CDS), direction (`inbound`/`outbound`), mTLS state, and matching `DestinationRule`. |
| **Filter by Port** | `istioctl pc cluster deploy/httpbin --port 8000` | Filters cluster configuration specifically for target port 8000. |
| **Output JSON / YAML** | `istioctl pc cluster deploy/httpbin --port 8000 -o json` | Dumps raw Envoy cluster JSON config (useful for checking TLS context, protocol settings, timeouts). |
| **List Listeners** | `istioctl pc listener deploy/httpbin` | Shows active ports Envoy is listening on (LDS). |
| **List Routes** | `istioctl pc route deploy/httpbin` | Shows active HTTP route tables (RDS) and associated `VirtualService` rules. |
| **List Endpoints** | `istioctl pc endpoint deploy/httpbin` | Shows live IP targets and health status for services (EDS). |
| **List Secrets** | `istioctl pc secret deploy/httpbin` | Shows loaded TLS certs and CA certificates (SDS). |

---

## 5. Envoy Proxy Dynamic Logging (`proxy-config log`)

| Task | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **View Active Loggers** | `istioctl pc log deploy/httpbin` | Dumps current log levels (`warning`, `info`, `debug`, etc.) for all Envoy subsystems (`http`, `router`, `envoy_bug`, etc.). |
| **Set Specific Log Level** | `istioctl pc log deploy/httpbin --level http:debug` | Dynamically increases log verbosity for a subsystem without restarting the pod. |
| **Set Multiple Log Levels** | `istioctl pc log deploy/httpbin --level http:debug,router:debug` | Changes multiple Envoy logger levels at once using comma separators. |

---

## 6. Traffic Debugging with Ephemeral Debug Containers

Use `kubectl debug` to attach an ephemeral container running `nicolaka/netshoot` directly to a pod sharing network/process namespaces with `istio-proxy`.

| Interface | Command | Use Case / Exam Focus |
| :--- | :--- | :--- |
| **Attach Netshoot Container** | `kubectl debug -it <pod-name> --image=nicolaka/netshoot --target istio-proxy` | Launches debug container targeted at the `istio-proxy` container in the pod. |
| **Capture Inbound/Outbound (eth0)** | `tcpdump -i eth0` | Captures external wire traffic between node network/clients and `istio-proxy`. |
| **Capture Proxy-to-App (lo)** | `tcpdump -i lo` | Captures decrypted plain-text traffic on `127.0.0.1` / `127.0.0.6` between `istio-proxy` and application container. |

## 7. Envoy Proxy Admin Dashboard

| Task | Command | What It Does / Exam Focus |
| :--- | :--- | :--- |
| **Open Envoy Admin Portal** | `istioctl dashboard proxy deploy/httpbin` | Port-forwards to Envoy native admin port (`15000`) and opens browser to inspect metrics, memory, runtime config, and server info. |

## 8. Exam Quick-Decision Matrix

| Scenario / Problem Description | First-Choice Command |
| :--- | :--- |
| "Resource applied but rules are not taking effect, check for config mistakes." | `istioctl analyze` |
| "Check if proxy configuration is pushed and synchronized with istiod." | `istioctl proxy-status` (or `istioctl ps`) |
| "Verify whether a VirtualService route or DestinationRule subset is active in Envoy." | `istioctl pc route` / `istioctl pc cluster` |
| "Check if Envoy has resolved endpoints/IPs for a service." | `istioctl pc endpoint` |
| "Inspect TLS/mTLS certificates loaded into Envoy." | `istioctl pc secret` |
| "Troubleshoot HTTP 503/502 errors at Envoy level without restarting pod." | `istioctl pc log <pod> --level http:debug` |
| "Inspect raw HTTP requests passing from sidecar proxy to local app container." | `kubectl debug ... --image=nicolaka/netshoot` + `tcpdump -i lo` |
| "Access control plane runtime options or change istiod log scopes." | `istioctl dashboard controlz deploy/istiod -n istio-system` |
