# 21.1 IstioOperator & Global MeshConfig Cheat Sheet

In the ICA exam, you are likely to be asked about **Outbound Traffic Policies**, **Custom Gateways**, or **Mesh-wide settings**. These are all managed via the `IstioOperator` CRD.

---

## 1. Top-Level Structure
An `IstioOperator` resource has four main sections you need to know:

```yaml
apiVersion: install.istio.io/v1alpha1
kind: IstioOperator
spec:
  profile: demo             # 1. Base profile (default, demo, minimal, empty)
  meshConfig: { ... }       # 2. Global settings for the whole mesh (behavior)
  components: { ... }       # 3. K8s resource settings for istiod/gateways (infra)
  values: { ... }           # 4. Legacy Helm-style pass-through settings
```

---

## 2. Important `meshConfig` Settings (Outbound Policy)
This is a high-probability exam topic. It controls if pods can talk to the internet by default.

```yaml
spec:
  meshConfig:
    # REGISTRY_ONLY = Block all traffic to services NOT defined via ServiceEntry
    # ALLOW_ANY     = Default. Allow all outbound traffic.
    outboundTrafficPolicy:
      mode: REGISTRY_ONLY 
    
    # Enable access logging for the ENTIRE mesh
    accessLogFile: /dev/stdout

    # Define the trust domain for mTLS identities
    trustDomain: cluster.local

    # Global Envoy settings (timeouts, etc.)
    defaultConfig:
      drainDuration: 45s
      proxyMetadata:
        # Example: Enable metadata exchange
        ISTIO_META_APP_CONTAINERS: "my-app"
```

---

## 3. Component Configuration & K8s Overrides
Use this to scale `istiod` or create custom Gateways with specific labels/ports.

### Example: Customizing Ingress Gateways
```yaml
spec:
  components:
    ingressGateways:
    - name: istio-ingressgateway
      enabled: true
      k8s:
        replicaCount: 3   # Scaling the gateway
        service:
          type: LoadBalancer
          ports:
          - name: status-port
            port: 15021
          - name: http2
            port: 80
          - name: https
            port: 443
          - name: custom-ext
            port: 9090    # Adding a custom port to the LB
        env:
        - name: PROXY_XDS_VIA_AGENT # Environment variable override
          value: "true"
```

---

## 4. The Profiles (Exam Comparison)

| Profile | Description |
| :--- | :--- |
| **`default`** | Recommended for production. Includes `istiod` and `ingress-gateway`. |
| **`demo`** | For learning. Includes `egress-gateway` and high trace sampling. **Heavy memory usage.** |
| **`minimal`** | Only `istiod`. No gateways. Good for internal-only meshes. |
| **`empty`** | Installs NOTHING. Use this to build a highly custom setup from scratch. |
| **`remote`** | For Multi-cluster Remote clusters. Only installs `base` (CRDs) and `cni`. |

---

## 5. Revision-based Installations (Canary)
If you are doing a canary upgrade, your `IstioOperator` must specify the revision:

```yaml
apiVersion: install.istio.io/v1alpha1
kind: IstioOperator
metadata:
  name: istio-1-22-1
spec:
  revision: 1-22-1 # This allows co-existence with a 'default' revision
```

## 6. Exam Quick Commands

| Task | Command |
| :--- | :--- |
| **Apply Operator config** | `istioctl install -f my-operator.yaml` |
| **Check installed version** | `istioctl version` |
| **Dry run (Check YAML output)** | `istioctl manifest generate -f my-operator.yaml` |
| **Verify installation** | `istioctl verify-install` |

---

### Why is this important for the exam?
*   **Outbound Traffic:** Many labs ask you to "Secure the mesh by blocking unauthorized external traffic." You do this in `meshConfig.outboundTrafficPolicy.mode`.
*   **Custom Labels:** If you need to map a `Gateway` (CRD) to a specific set of pods, you might need to change the labels on the ingress gateway deployment via `components.ingressGateways[0].label`.
*   **Scaling:** If `istiod` is crashing under load, you'll need to increase `components.pilot.k8s.resources.requests`.
